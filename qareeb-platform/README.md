# قريب — محاكاة رحلة المريض

تطبيق React/TypeScript عربي أولاً يحاكي رحلة تحديد عرض دوائي دقيق، الموافقة
على الوصفة، طلب توفر مجهول، نبض أحداث صيدليات، وحجز مؤقت. التنفيذ يتبع
[`SPEC.md`](./SPEC.md) و[`DESIGN.md`](./DESIGN.md).

> هذه محاكاة ثابتة وليست نظاماً صحياً إنتاجياً. لا مخزون أو صيدليات أو Gudea أو
> KMS حقيقية متصلة، ولا يجوز استخدامها للصرف أو لإدارة وصفات مرضى حقيقية.

## موقع هذا المجلد من المستودع

المستودع يحوي الآن تنفيذين لنفس المنتج، ولم يُدمجا:

| | `hub/` | `qareeb-platform/` (هنا) |
|---|---|---|
| البناء | vanilla JS بلا خطوة بناء ولا اعتماديات | React 19 + TypeScript + Vite |
| النطاق | دليل بغداد + مستكشف الدواء الوطني + وحدة المشغّل | رحلة المريض S0–S5 مع حراس نطاق واختبارات |
| النشر | حيّ على `qareeb-iq.netlify.app` | غير منشور |

أيّهما يصير الأساس قرار منتج لم يُتّخذ بعد. لا تنسخ كوداً بين الاثنين قبل ذلك
القرار — الاثنان يحملان نفس الأسماء لمفاهيم مختلفة.

## التشغيل المحلي

يتطلب Node.js 22 أو أحدث:

```bash
cd qareeb-platform
npm ci
npm run dev
```

افتح العنوان الذي يطبعه Vite، عادةً `http://localhost:5173`.

التحقق الكامل:

```bash
npm run check
npm test
npm run build
npm run preview
```

اختبار المتصفح الاختياري يستخدم Python Playwright وGoogle Chrome المحلي:

```bash
python3 -m venv /tmp/qareeb-playwright-venv
/tmp/qareeb-playwright-venv/bin/python -m pip install playwright
npm run preview -- --host 127.0.0.1
# في طرفية ثانية؛ عدّل المنفذ إذا اختار Vite منفذاً آخر:
QAREEB_BASE_URL=http://127.0.0.1:4173 \
  /tmp/qareeb-playwright-venv/bin/python scripts/browser_check.py
```

الصور الناتجة تُحفظ خارج المستودع في `/tmp/qareeb-browser`.

## حالات العرض

من شاشة الاكتشاف اختر حالة ثم اضغط «تثبيت هوية الدواء»:

- **حجز ناجح:** تأكيد عرض وسعر، تطابق، مرجع فريد، ثم حجز مؤقت.
- **بدون وصفة:** طلب OTC مباشر.
- **بوصفة:** موافقة صريحة، تشفير AES-256-GCM، ووصول صيدلي مدقّق.
- **دواء خاضع:** يمنع البث العام ويعرض تسليماً آمناً لصيدلية مرخصة.
- **اسم ملتبس:** يفرض اختيار القوة والشكل والطريق والعبوة.
- **Gudea غير متاح:** يظهر الفشل بوضوح ولا يوقف الرحلة.
- **اعتذار الصيدليات:** النتيجة مشتقة من أحداث اعتذار فعلية في المحاكي.
- **انتهاء المهلة:** لا يظهر حجز أو ادعاء توفر عند غياب التأكيد.

كل أسماء الصيدليات والعناوين والأرقام والأسعار والأحداث في العرض تجريبية.

## الحدود المعمارية

- `src/domain/`: عقود نقية، انتقالات S0–S5 محروسة، تشفير الوصفة، حمولة البث
  المسموح بها، سجل تدقيق hash-linked، محوّل Gudea، وقواعد الحجز/الانتهاء.
- `src/simulation/`: مصدر أحداث مؤرخ يمر عبر حراس النطاق نفسها؛ لا نسب تقدم أو
  نشاط مفترض.
- `src/data/`: كتالوج عروض وأسماء بديلة عربية/كردية/إنجليزية للعرض فقط.
- `src/ui/` و`src/App.tsx`: رحلة RTL، Shelf Pulse، سجل الثقة، وحالات الفشل.
- `netlify.toml` و`public/_headers` و`public/_redirects`: بناء SPA ورؤوس أمان
  قابلة للنشر على Netlify.

التشفير التجريبي يولد مفتاح بيانات AES-256-GCM ومفتاح تغليف مؤقتاً في المتصفح
ثم يفقد مفتاح التغليف؛ وهو إثبات للحد التشفيري فقط، وليس دورة مفاتيح قابلة
للاسترداد. سجل التدقيق hash-linked داخل الذاكرة، لكنه غير محمي بصلاحيات قاعدة
بيانات أو WORM.

## نشر Netlify يدوياً

المصدر مرفوع الآن إلى مستودع `adlytic` داخل مجلد `qareeb-platform/`، لكن **لم
يُنشأ أي مشروع Netlify لهذا التطبيق ولم يُنشر**. مشروع `qareeb-iq` القائم يخدم
تطبيق `hub/` وحده، ولا علاقة له بهذا البناء.

1. شغّل `npm ci && npm run check && npm test && npm run build`.
2. تحقق من وجود `dist/index.html` و`dist/_headers` و`dist/_redirects`.
3. في Netlify اختر **Add new site → Deploy manually**.
4. اسحب مجلد `dist/` إلى منطقة الرفع.
5. بعد النشر، تحقق من تحويل مسارات SPA ومن رؤوس CSP و`X-Content-Type-Options`.
6. لا تضع أسراراً في متغيرات `VITE_*`؛ أي قيمة منها تصبح عامة داخل المتصفح.

بديل الربط بمستودع لاحقاً: base directory هو الجذر، build command هو
`npm run build`، وpublish directory هو `dist`. إعدادات `netlify.toml` جاهزة،
لكن إنشاء remote أو ربط Netlify خارج نطاق هذا التسليم.

## ما يلزم للإنتاج

قبل أي استخدام حقيقي يلزم تنفيذ واعتماد ما يلي خارج التطبيق الثابت:

- API خلفي وHTTPS مفروض عند الحافة، مع قاعدة بيانات وصلاحيات tenant مناسبة.
- envelope encryption عبر KMS مُدار، وتخزين كائنات مشفّر، وحذف فعلي قابل
  للتدقيق بعد مدة الاحتفاظ.
- مصادقة صيدلي قوية، تحقق ترخيص من الجهة المختصة، وربط الوصول بالصيدلية
  المقبولة فقط.
- سجل تدقيق غير قابل للتعديل بفرض صلاحيات قاعدة البيانات أو WORM.
- عقد Gudea مصرح به والتحقق من تطابق هوية العرض، مع timeouts ومراقبة.
- بنية أحداث موثوقة (SSE/WebSocket أو ما يعادلها)، idempotency، replay،
  timestamps موثوقة، ومراقبة انقطاع الاتصال.
- خدمات طلب/استجابة صيدليات، hold ذري وفريد، انتهاء server-side، وتأكيد صرف.
- مراجعة تنظيمية وقانونية وأمنية، إدارة موافقات، وسياسة خصوصية واستجابة حوادث.
