# دوائي — Dawai

تطبيق ويب كامل ثنائي الأطراف يربط المريض الذي يحتاج دواءً بصيدليات موثقة وقريبة
تستطيع تأكيد التوفر والسعر والجاهزية.

## المنتج المنفذ

### المريض

- تسجيل ودخول وحساب شخصي.
- بحث مباشر في إشارات التوفر الحديثة.
- طلب دواء بالاسم أو الوصف مع صورة علبة/وصفة اختيارية.
- تحديد GPS أو منطقة يدوية.
- مطابقة جغرافية 2→5→10 كم.
- عروض حقيقية من الصيدليات مع حداثة التأكيد والسعر.
- اختيار عرض مطابق وطلب حجز.
- متابعة تأكيد الصيدلية، الجاهزية، الاتجاهات، الاتصال، والمحادثة.
- سجل الطلبات والصيدليات المحفوظة والإشعارات.

### الصيدلية

- حساب منفصل وتهيئة الفرع والترخيص والموقع والساعات والخدمات.
- رفع وثائق تحقق مشفرة.
- حالة Pending/Verified/Rejected/Suspended صادرة من الإدارة فقط.
- لوحة مؤشرات وصندوق طلبات مطابق للموقع والساعات.
- اعتذار أو عرض مطابق/جزئي/قابل للتوفير/بديل للمراجعة.
- تأكيد الحجز ثم Ready ثم Complete أو Fail.
- إعدادات ساعات العمل والاستلام والتوصيل والطاقة التشغيلية.

### الإدارة

- حساب Admin محمي وصلاحيات مفروضة على الخادم.
- مراجعة ملف الصيدلية والوثائق مع سجل وصول.
- اعتماد/رفض وتعليق/استعادة الصيدليات.
- إدارة المستخدمين وتعليق الجلسات.
- تتبع request → dispatch → offer → reservation.
- البلاغات وسجل التدقيق.

## البنية

```text
React RTL client
       │ REST /api/v1 + cookie or bearer session
       ▼
Hono modular API
       │
       ├── PostgreSQL production / PGlite local and tests
       ├── encrypted private file store
       └── durable notifications + outbox
                    │
                    └── lifecycle worker
```

- معرفات وجلسات عشوائية؛ لا توجد صلاحيات موثوقة في العميل.
- CSRF + Origin checks للويب، وBearer صالح لعميل native مستقبلًا.
- Idempotency للطلبات والعروض والحجز.
- AES-256-GCM بعد فحص magic bytes وإعادة ترميز الصورة وإزالة EXIF.
- الحجز يبدأ بعد إقرار الصيدلية، وليس عند اختيار المريض.
- البديل الدوائي لا يمكن حجزه تلقائيًا.

التفاصيل: [`ARCHITECTURE.md`](./ARCHITECTURE.md).

## التشغيل المحلي

يتطلب Node 24 وفق صورة الإنتاج.

```bash
npm ci
npm run dev
```

يعمل API على `8787` والويب على `5173`. يستخدم التطوير PGlite محليًا. لا توجد
حسابات أو صيدليات أو عروض وهمية. بيانات الدواء المرجعية الأولية منفصلة عن
بيانات التوفر.

لإنشاء أول مشرف محليًا:

```bash
ADMIN_EMAIL=admin@example.test \
ADMIN_PASSWORD='use-a-strong-password' \
npm run dev
```

احذف متغيرات bootstrap بعد إنشاء الحساب.

## الإنتاج

انسخ `.env.example` إلى إدارة أسرار فعلية، ولا تضع القيم في Git:

```bash
docker compose up --build
```

الإنتاج يرفض التشغيل دون PostgreSQL ومفاتيح الجلسة والتشفير. شغّل migration
كعملية منفصلة قبل API، كما هو معرف في `compose.yaml`.

## التحقق

```bash
npm run check
npm test
npm run build
npm run test:e2e
npm audit
```

اختبار المتصفح يبني رحلة كاملة على الهاتف وسطح المكتب عبر المريض والصيدلية
والإدارة، وليس mock network.

## ملاحظات تشغيلية

- OCR موصل معماريًا عبر رفع آمن، لكن لا يدّعي استخراجًا عند غياب مزود موثوق.
- إشعارات in-app وoutbox منفذة؛ APNs/FCM/Web Push تستهلك نفس outbox لاحقًا دون
  تغيير API أو نموذج البيانات.
- التخزين المحلي المشفر مناسب لعقدة واحدة. التشغيل متعدد العقد يجب أن يستخدم
  object storage خاصًا وKMS مع نفس عقد `secure_files`.
- يلزم اعتماد قانوني عراقي اتحادي/KRG قبل معالجة وصفات أو توصيل أدوية حقيقية.
