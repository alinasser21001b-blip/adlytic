Reservation state machine (live)

All machines

  • Request (live) — DRAFT→ACTIVE→HOLD_PENDING→RESERVED→READY→COMPLETED, with NO_MATCH→ACTIVE only via explicit patient expand
  • Offer (live) — ACTIVE→HOLD_PENDING→HELD→FULFILLED, or WITHDRAWN/SUPERSEDED/EXPIRED/FAILED
  • Reservation (live) — see diagram above
  • Pharmacy verification (live) — PENDING→UNDER_REVIEW→VERIFIED/REJECTED, VERIFIED↔SUSPENDED
  • Request / Offer / Reservation / Subject / Grant / Verification / Branch-eligibility / Outbox (spec, v3) — generic defineMachine()-backed tables in @dawai/domain, each edge Blueprint-referenced

Navigation philosophy

dawai-platform (live)

One SPA, one router, all three roles in one bundle. Role isolation is enforced server-side (every request re-checked), not by separate builds. No native app yet — Capacitor remote-URL shell recommended for iOS.

Blueprint v3 (spec)

Role isolation is structural: three separate builds (Patient / Pharmacy / Owner Console), verified by an import-check at build time — "a patient build contains no pharmacy route, so the class of leak v1 hit twice is unrepresentable." Guards: requireSession, requireSubjectScope, blockMemorialised, requireStaffSession, requireManager, requirePharmacist, requireVerified, requireOperator.

Events & notifications

Live: no message broker — events are durable rows (notifications, notification_outbox, attention_events, audit_events) written synchronously, consumed by the 30s worker sweep or client polling. Outbox payload is always minimal: {eventType, resourceId} — never PHI.

Spec (v3): a formal 54-event catalogue, each with a declared producer and ≥1 consumer, at-least-once delivery, and a stated idempotency key — "a duplicate dispense record or reservation would be a clinical defect, not an inconvenience."

⚠ Clinical safety — read before editing this code

  • rule Interaction checks fail closed to UNAVAILABLE — never a false "clear"
  • rule dose_events, stock_movements, audit_events are append-only — corrections are new rows
  • rule SEV_ALERT attention events never expire and are never dismissible except by resolving their cause
  • rule Only a pharmacy account may set sig_source = PHARMACIST
  • rule The 15-minute hold starts only on pharmacy acknowledgement
  • rule A non-selected pharmacy can never access a prescription image
  • rule Low-trust SKUs are excluded from forecasting entirely, never shown with a caveat

Full reasoning + a pre-edit checklist: 10-clinical-safety.md
