## Breaking change: `safety-alert@3.0.0`

The safety-alert contract carries `breakingChange: true`. Consumers pinned to
`2.x` must move before upgrading. The validator refuses to ship a breaking
clinical contract inside a patch release, because a breaking safety change
concealed in a patch version is the most dangerous shape a release can take.

## Release governance is now enforced

`release-manifest.yaml` is the sole source of truth. If you previously read a
version number from a compatibility document, a changelog heading, or the
governance dashboard, read it from the manifest instead — those files are now
generated and will be overwritten.

```bash
node tools/release/validate.mjs   # gate
node tools/release/generate.mjs   # regenerate outputs
```

Human-written release documents may use the placeholder tokens
`{{platform}}`, `{{knowledge}}`, `{{policy}}`, `{{releaseId}}`, and
`{{status}}`. The generator fills them at build time.

## Feature flags

`interaction_priority_rules_v3` has high clinical impact and may not be enabled
in an approved snapshot. `safety_alert_new_copy` requires a recorded clinical
approval before it can be turned on.
