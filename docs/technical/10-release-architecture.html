Release Architecture

The release process is not new. It already exists in this repository and is reused: release-manifest.yaml is the sole operational source of truth, with ten validators and a generator that can prove no output was hand-edited.

Single source of truthrelease-manifest.yaml — release identity, compatibility, governance policy, approved runtime configuration, verification status and artifact paths. Every number that appears in a changelog, release note, compatibility report or dashboard is read from it. Nothing is written twice.

Validation gates for status: released

  1. Manifest schema valid
  2. Policy version supported
  3. All declared contracts compatible
  4. Architecture validation: 11/11
  5. Every permission-matrix cell exercised
  6. Runtime configuration hash matches the approved snapshot
  7. Every required verification has a signed, hashed evidence file
  8. All generated artifacts match the manifest
  9. All release-gate approvals completed

Rollback

LayerStrategy
ClientStore rollout is staged; a halt stops the rollout, and the previous build remains installable. Clients never assume the newest server contract — a version below the manifest's minimum is told to update rather than failing obscurely.
ServiceDeploy is blue/green per service. Rollback is repointing traffic; no data migration is reversed by a rollback.
SchemaExpand-migrate-contract. A release never contracts in the same deploy that expands, so the previous service version always runs against the new schema.
Append-only tablesdispense_records and audit_entries are never rolled back. A rollback that could erase a clinical record or an audit entry is not a rollback; corrections are new records.
Feature configurationToggling is instant and does not require a deploy. Every toggle has an owner and a removal version, and one past its removal version blocks the release.
What a rollback can never do Erase a dispense record or an audit entry. Those tables are append-only in both directions of time — a rollback that could remove a clinical record is not a rollback, it is data loss with a friendly name. Corrections are new records.
